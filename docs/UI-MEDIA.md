# 页面风格与图片加载

## 统一样式

`src/theme.css` 集中定义颜色、字体、圆角、间距和交互控件样式。商城、业务后台、风控档案和钢贸工作台共用白底、蓝色主操作与浅蓝选中态。绿色表示成功，橙色表示待处理/预警，红色表示错误或风险结果；保留业务状态含义。

## 图片加载

`src/components/CategoryPhoto.jsx` 统一使用本地响应式照片。浏览器依据 `srcSet`、各展示位置的 `sizes` 和设备像素比选择图片。首屏主视觉立即加载并提高优先级，其余图片延迟加载，图片声明固有尺寸并异步解码。优化文件加载失败后尝试原始照片，再失败则显示可访问的占位提示。

- 原始照片与许可：`src/data/catalog-media.json`、`public/images/ATTRIBUTION.md`。
- 派生映射与 SHA-256：`src/data/catalog-images.json`。
- 派生文件：`public/images/optimized/`，宽度 160 / 384 / 768 / 1280px；不放大原图。
- 文件名包含内容哈希；Java 为这些文件及 Vite `/assets/` 设置一年 `immutable` 缓存。原始照片缓存一天，HTML 保持重新验证，认证及业务 API 继续 `no-store`。

原始照片不变，派生图仅作转码及缩放，不改变摄影内容，不代表具体供应商库存或检验资料。此次 17 张原图共 8,349,685 字节，对应 384px 派生图共 289,558 字节，减少约 96.5%。实际请求尺寸依浏览器和展示位置变化，此比例并非整站加载速度提升比例。

## 维护

添加或更新照片后，先维护原图来源、许可及校验值，再生成派生文件：

```sh
# 开发环境需要 Python 3 与 Pillow（支持 WebP）。生产构建直接使用已提交文件。
npm run optimize:media
npm run check:media
npm run build
```

生成器保留旧哈希文件，避免已有缓存页面请求的图片立即失效。提交新清单和对应派生文件；不要覆盖同名内容哈希文件。图片缓存策略需要同时部署 Java 后端。

验证覆盖主视觉优先级、响应式选择、静态缓存与 API 不缓存、原图回退、最终占位，以及商城/后台控件颜色和移动端宽度。
