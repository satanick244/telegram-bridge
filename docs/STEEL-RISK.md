# 钢贸风控第一版

从已登录工作台侧栏进入「钢贸风控」。沿用原有账号和会话；普通账号只操作本账号档案，平台管理员可审核各账号资料。不会导入或自动创建虚构客户、供应商、授信或交易数据。

## 试运行范围与参数

- 默认不自动授信，未获批额度为 0。授信申请、订单占额、收款核销和取消释放都由管理员写明理由后审批；不执行付款、发货、放货，不替代现有订单履约控制。
- 默认逾期 1 天预警、7 天升级；按 UTC 自然日计算。第一版由用户点击「扫描并生成预警工单」，无后台定时扫描。已处理工单保留；同一订单同类预警不重复建单，升级单独建单。
- 默认钢材成本不利变动 5%、汇率不利变动 3%、运费增加 10%。管理员在「试运行参数」调整并填写理由，产生新版本；已有评价、申请和审批快照保留旧版本。
- 以上只是可配置初始假设，没有经过历史数据校准，不输出“低风险”判断。未知输入存为 null，页面显示「资料待补齐」。零成本/零运费必须明确录入 0。

## 推荐操作顺序

1. 建立客户或供应商风险档案，填业务唯一键、资料来源和凭据索引。注册、财务、履约资料未知时留空，之后可「补充资料」；每次修改须理由和版本校验。
2. 在「订单与压力测算」登记风险合同。客户对应销售合同，供应商对应采购合同。风险合同不会创建平台交易订单。可关联本账号现有平台采购订单，此时方向、金额、币种、数量、单位和条款须与该订单一致，且不能重复关联。
3. 真实客户申请分币种授信总额度，经管理员批准后生效；不是在旧额度上累加。资料不足时，申请人须明确勾选缺失资料确认，管理员填写接受风险的依据。不能把总额度调到低于当前占用。
4. 真实销售赊销合同申请占额。必须有明确正数金额、币种和到期日，并已获足够授信。资料缺失不会被当作零；只有明确确认缺口并人工审批才可占额。
5. 银行到账后，用银行流水号等业务唯一键提交收款核销申请，写明凭据索引。管理员核验通过后减少应收并等额释放占用，支持部分收款；金额必须与订单同币种，不能超过剩余本金。风控账不是银行账户，上传索引不代表系统已独立核实到账。
6. 错录或取消合同使用「取消并释放」申请。未占额合同可审批取消；已占额合同释放剩余占用，保留已收款记录。取消释放不记作收款，也不取消原平台交易订单。合同金额不提供覆盖修改接口，需取消后用新的唯一键重建。
7. 扫描预警，分配负责人（资料所属账号或平台管理员），记录处理说明及状态。规则调整、资料修改、评价、导入、工单和审批均进入审计。

管理员可以处理本人提交的申请；第一版没有强制双人分离审批，如需四眼原则需另行实施权限和组织流程。

## 金额、成本与敞口口径

当前支持 USD 和 CNY，金额按最小货币单位整数存储，最多两位小数。授信按「所属账号 → 客户 → 币种」隔离，USD/CNY 不相互抵扣，客户与供应商也不相互抵扣。应收本金占额仅记一次合同总额；成本、运费和压力损失不会再次加入占额。成本/测算超出整数精度时返回资料缺口，不输出伪精确数值。

数量明确单位；材料成本的每单位必须与合同匹配，只提供吨与千克的确定性换算，不猜测件、套、米、双之间的换算。贸易条款保留为输入，但不凭 FOB/CIF 等标签自动推断费用承担；用户须明确本方/对手承担运费及合同金额是否含运费。

压力情景以 CNY 报告，使用手工输入的 CNY/USD 汇率，不接实时行情。材料成本上升、运费上升后，再按净 USD 收入减成本的方向施加不利汇率；币种相同的收入与成本先净额计算。合同已含运费时不再增加收入；本方运费单独等额收取时仅增加一次等额补偿。对手承担的运费不计本方成本。采购合同不把采购总额当作销售收入，仅给出已明确的材料/运费成本测算。

这里的“毛利”为**仅材料与运费的局部测算**，不含未知税费、保险、资金成本、平台费或套保收益，不等于完整利润或可放货结论。预估、示例可用于测算，但不能进入真实授信、占额和核销；真实资料的派生压力结果仍是预估结果。

## 导入与来源

「数据导入」提供 CSV/JSON 空白字段模板、本地文件读取、内容预览与编辑。每批最多 200 行、80 KB，任一行失败则整批回滚。批次唯一键防止重复导入，同一键携带不同内容会冲突；行内业务唯一键也用于去重。不会按企业名称跨账号合并。

- 档案 JSON 示例（空字符串表示未知；仅用于说明，系统不自动写入）：
  ```json
  [{"businessKey":"客户内部编号","name":"实际企业名称","partyType":"customer","country":"","registration":"","financialEvidence":"","performanceEvidence":"","notes":""}]
  ```
- CSV 表头与 JSON 字段名一致。partyType 为 customer/supplier，direction 为 sale/purchase，paymentMode 为 cash/credit，freightPayer 为 self/counterparty，freightIncluded 为 true/false。
- 订单 profileId 从本账号档案快照获取；关联平台订单使用 platformOrderId。币种 USD/CNY，条款 EXW/FOB/CFR/CIF/DAP/DDP。
- 导入时必须标记真实/预估/示例，并记录文件来源、批次和行号。真实导入标记 source=import，预估和示例保持对应性质，另记 inputMethod=import。直接录入的真实资料标记 source=manual。
- 不允许文件指定 ownerId、审批状态、占用余额或审计数据。导入不会自动授信、占额或核销。收款凭据需在收款申请中单独核验。

## 存储、审计及备份

SQLite 新增 risk_records、risk_audit、risk_locks；MySQL 对应 ip_ 前缀表。启动只新增表和初始化锁，不修改/清空既有业务表或数据。MySQL 使用 InnoDB 事务，并先锁定持久化 operations 行，跨连接串行化风控写操作；这是第一版的保守一致性策略，后续可按业务分区提高并发。唯一业务键派生记录主键，审批重放保持幂等，失败整笔回滚。

审计包含操作者、时间、理由、输入来源、资料/规则/评价快照和前序哈希。应用存储层拒绝 audit 的 put/remove，SQLite 另外使用触发器禁止 UPDATE/DELETE；MySQL 不要求额外触发器权限。管理员可校验完整链。哈希链可检测一般记录变更，不抵御持有数据库超级权限者重写全链；仍需外部备份和数据库最小权限管理。

企业设置的管理员迁移备份现在包含三个风控表与完整审计根。`scripts/import-backup.mjs` 支持校验完整链后恢复，并拒绝与目标库已有记录冲突；禁止仅拷贝部分审计记录。备份含密码哈希及业务资料，须私下保管。脚本仍限制文件 32 MB、每表 50,000 条，超限须另行制定受控迁移方案；旧版不含风控表的备份仍可导入。

## 验证与部署

- `npm test`：接口/领域、风控权限、币种与单位、未知输入、审批、重复和并发操作、导入回滚、规则快照及审计。
- `npm run test:e2e`：生产构建和 Chromium 流程，包含风控入口、资料缺口、授信审批、导入、审计及手机布局。
- `MYSQL_TEST_CONFIG_FILE=/private/test-config.json node --test --test-concurrency=1 tests/mysql.integration.test.js tests/risk-mysql.integration.test.js`：隔离的 localhost MySQL 5.7 测试库，库名须 `_test` 结尾。验证跨连接占额/核销、事务回滚、重开存储与完整快照幂等导入，禁止连接生产库。

仅更新 Render `induport-trade`（srv-dbhv45psrm7s73e27t90），保留线上 MySQL 和管理员环境变量。使用 render-induport.yaml，不修改旧 render.yaml 或其他服务。手动部署指定提交后确认部署状态 live、提交 SHA 一致，并检查 `/api/health` 返回 database=mysql、riskVersion=steel-risk-v1。线上不自动写入测试交易或授信。

## 只读案例体验

登录页新增买家和供应商两个只读演示入口。演示规则、档案、合同、工单和额度算例均明确标注来源，常规真实账号的风控视图不包含这些资料。额度算例不进入真实账本，不提供演示管理员审批。详情见 [DEMO-ACCOUNTS.md](DEMO-ACCOUNTS.md)。
