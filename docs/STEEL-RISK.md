# 钢贸风控第二版：应收、资金与发货闭环

登录后从「钢贸风控」进入。系统沿用原有买家、供应商、管理员账号与 HttpOnly 会话；真实业务按所属账号隔离，演示/预估不能记入真实资金或发货审批。第二版以人工凭据核验为基础，不直接连接银行或仓库执行收款、退款、发货、放货。

## 核心账务口径

以销售合同的本金作为单一敞口，不把材料成本、运费、压力损失再次加入信用占用。

- **未开票承诺 → 已开票应收**是阶段转换，登记应收不会再占一次授信；应收总额不能超过合同本金。
- **到账登记 → 独立确认 → 分配核销**是三个不同状态。已确认但未分配的资金不自动减少应收，也不自动释放占用。
- 一笔真实到账可以分配到同账号、同客户、同币种的多笔应收。一笔应收也可以分次收款；跨币种不做自动折算核销。
- 发票/应收编号按账号唯一，到账按「本方账户别名 + 银行流水号」唯一。引用统一做 NFKC/大小写规范化。录错后走作废/冲销，不用覆盖原记录。
- 核销批准后，增加应收已收金额，减少合同未收本金；已占额合同同步等额释放信用占用。现款或尚未占额的合同不凭空创建授信。
- 已确认预收款可先核销登记的应收，再仅对剩余未收本金申请占额。新客未获批授信时，可登记事实性应收，但显示未覆盖本金，不能据此发货。
- 全额收款的现款合同可以在其他条件满足后申请发货；银行“确认”本身不能替代应收“核销”。

所有金额使用 USD/CNY 最小货币单位整数存储，最多两位小数。不同币种分账，未知合同金额显示待补齐，不按零授信或零风险处理。这里的应收登记口径须与合同本金一致，不是完整税务开票或总账系统。

## 准备角色与客户档案

业务账号登记合同、资金和申请；另一位管理员复核。**申请人/到账录入人不能审批或确认自己的操作**。有一位管理员和一个独立业务账号即可使用；系统按不同账号实施分离，仍需组织管理确保账号由适当人员使用。

客户档案增加「平台对手账号」。绑定真实平台销售订单时，必须满足：

1. 档案属于该订单供应商账号；客户绑定的账号等于实际买家账号。
2. 合同金额、USD 币种、数量、计量单位和贸易条款与订单一致。
3. 同一订单同一方向只有一个未取消风险合同。买家采购风险合同与供应商销售风险合同可各自存在，各自账户内不重复占额。

已绑定的对手账号不能直接换成另一客户。客户资料版本变化后，原授信须重新复核；不能用甲客户额度支持乙客户订单。预估/示例不能绑定真实订单，旧的纯测算合同可由所属账号归档，真实财务合同须经取消/冲销流程处理。

## 授信与占额

在「授信与收款」提交总额度、币种、有效期、最长账期、可选单笔未收本金上限和授信条件。默认不授信、不自动批准。

管理员审批时再次检查条件及当前占用；总额度不能低于已占用金额。授信保存客户档案版本、规则版本、申请人、审批人、理由、有效期和条件。客户资料变更、有效期过期、冻结、单笔超限或账期不符会阻断新增占额和有敞口的发货。

旧版本未设置有效期/账期或未记录档案版本的授信保留余额，标记需重新审批，不自动补上有效期。旧的已批准操作不被重写；旧待审直接收款申请须改用新的到账核销流程。

管理员可附理由冻结授信。解除冻结通过新的独立授信审批办理，不提供随意改余额或直接开关放行的接口。冻结和重新审批均保留审计。

## 资金与应收操作

进入「资金与应收」：

1. **登记应收**：选择真实销售合同，填发票/应收编号、金额、开票日、到期日、依据索引。可分多次登记；不超过合同本金。
2. **登记到账**：选择真实客户，填本方收款账户别名、银行流水号、金额币种、付款方、到账日期和凭据索引。不填银行密码或 API 密钥。
3. **独立确认**：另一位管理员核对资金实际到账、付款主体、金额和币种，并填写独立核验凭据与理由。这是人工核验记录，不表示系统已接入银行。
4. **分配核销**：业务账号把已确认款项分配到同客户、同币种应收（每批 1–50 行）；另一位管理员独立批准后原子更新资金分配、应收余额、合同本金和信用占用。超额或任何一行失败时整批回滚。
5. **冲销/作废**：错误核销通过反向批准批次更正，保留原批次和反向引用，不执行银行退款。到账已分配时须先冲销再作废；应收已有收款或已发货时不能直接作废，需另行办理受控退货/贷项流程。

核销冲销会恢复真实债务及占用，不能因为新额度已经调低就隐藏债务；恢复后超额会冻结授信。所有决策与流水使用事务和唯一业务键，重复点击不重复核销或释放。

### 历史期初核销对账

历史已核销金额单独显示为「历史待对账」。有历史记录时，可把它们关联到同合同的应收并提交独立复核：只增加应收关联，不新增到账，不再次释放授信。可通过反向批次解除错误关联。历史金额未逐笔关联前不能取得新的发货放行。

## 发货复核与执行

供应商将真实订单推进至「待装运」后，在「发货复核」提交合同确认、货权/放货、质检与装运资料依据。

**硬条件**包括真实身份与对手绑定、合同与订单一致、应收覆盖完整本金、历史核销已对齐、现款全额核销或赊销完成有效占额、赊销授信未冻结，以及相关客户应收的覆盖情况。硬条件不能用例外理由绕过。

**人工风险提示**包括客户财务/履约依据不足、测算输入不足、压力亏损和客户逾期余额。管理员必须独立核对客户、货权、质检装运依据；接受软风险时须明确例外批准、依据及补偿措施，不能默认为通过。

批准有效 24 小时，只能使用一次。它保存审批时客户、规则、授信、应收、核销、订单和工作流政策快照。订单详情选择有效批准，点击「更新状态：运输中」时，在同一事务内再次校验，消费批准并更新订单：

- 余额、客户档案、规则、冻结或订单状态变化导致快照不一致时，旧批准不能使用，须重新申请。
- 重复提交同一发货批准返回既有运输状态，不会顺便把订单推进到已完成。
- 已运输中/已完成的历史订单不追溯阻断；所有尚未发货的真实订单进入运输中时均须有有效审批，未绑定销售风控合同也不能绕过。
- 系统更新的是业务状态，没有向真实仓库、承运人或银行发送执行指令。

首版发货控制按完整订单核验，不支持分批发货、额度续作、跨币种冲账、自动银行对账、实际退款、退货贷项或关联企业授信合并。这些需要后续独立流程，不能据此称为完整 ERP/仓储或征信系统。

## 测算、预警与案例

钢价不利 5%、汇率不利 3%、运费增加 10%，逾期 1 天预警、7 天升级，仍是可由管理员修改的试运行假设，未经历史数据校准。账龄按 UTC 自然日计算。当前预警工单由人工扫描，不是定时后台催收。

数量明确计量单位，只自动换算吨/千克；USD/CNY 成本按手工 CNY/USD 汇率计算。必须显式说明贸易条款、费用承担方、合同是否含运费，避免重复计费。压力毛差仅含已建模的材料和运费，不是完整净利润，也不能替代客户、货权、资金和单证核验。

9 组只读演示情景继续独立运行；真实核验与情景输入完整性分开。演示账号可以查看闭环流程说明，不能创建真实资金、应收或发货批准，详见 [DEMO-ACCOUNTS.md](DEMO-ACCOUNTS.md)。

## 技术与验证

继续使用既有 risk_records、risk_audit、risk_locks 表，MySQL 带 ip_ 前缀；不重置已有资料、不引入新收费服务。关键财务/发货操作首先锁定持久化 operations 行，统一锁顺序后再处理交易订单，保证跨连接一致性。应用审计只能追加，哈希链可检测一般变更；数据库超级权限仍须最小权限管理及外部备份。

管理员迁移备份包含所有风控、资金和审计记录；导入仍校验完整链、文件大小及冲突，不支持覆盖已有数据。只在受控停服窗口执行恢复，不与在线财务写操作并行。

运行 `npm test`、`npm run test:e2e`。隔离 MySQL 测试使用 localhost `_test` 库及 MYSQL_TEST_CONFIG_FILE，禁止连接生产库写测试财务数据。线上仅检查健康、鉴权和只读演示；真实带凭据闭环在隔离测试库验证。
