# SteelFlow 产品设计说明

## 产品定位

面向中小钢厂、钢贸出口商与海外 B2B 买家的交易协作平台。以标准化商品目录为入口，通过询价、合同订单和履约协作完成交易。钢贸存在价格波动、规格差异、大宗运输与账期协商，不能直接照搬普通消费电商的即时支付逻辑。

核心路径：供应商申请 → 平台核验 → 出口商品上架 → 买家选品 / 询价 → 报价协商 → 采购订单 → 合同及付款条件确认 → 生产备货 → 出口装运 → 交付 → 对账结算。

## 三类角色

| 角色 | 商用版本的职责与权限 | 当前实现 |
| --- | --- | --- |
| 供应商 | 管理本企业商品、采购成本、报价、订单、单证和收益 | 演示空间的完整操作流程 |
| 买家 | 采购搜索、询价、提交订单、查看自己企业的订单及单证 | 采购与询价流程；未做企业隔离 |
| 平台运营 | 企业资质审核、类目与商品治理、费率配置、争议与履约协助 | 入驻演示审核与平台目录 |

真实版本必须在服务端识别身份与企业边界。买家不应读取供应商采购成本和收益，供应商不应读取其他企业数据。当前演示 API 聚合整个工作空间的数据，不代表商用权限方案。

## 商品结构

必填：供应商、中文名称、品类、钢种牌号、尺寸规格、出口单价、采购成本、库存、最小起订量、贸易条款、装运港。

补充：英文名称、质量标准 / 认证、交货周期。

后续：厚度 / 宽度 / 长度的结构化参数、执行标准、表面处理、镀层、HS 编码、炉批号、材质证明、真实图片、包装方式、阶梯价格、报价有效期和目的市场适用标准。

## 交易与履约

- 商品价由服务端读取，拒绝客户端篡改金额；库存预留与订单创建在 SQLite 事务中一起提交。
- 采购数量必须为整数吨，达到最小起订量且不超过可售库存。
- 当前所有订单属于不收款的演示订单。合同确认、生产、装运和完成由操作者演示推进，并记录状态历史。
- 真实版本需要区分报价有效期、合同确认、付款状态和履约状态；不能用履约状态代替付款凭证。
- 后续增加多行订单、取消及库存释放、预留超时、幂等请求、信用额度、分批发货和异常处理。
- 税率、付款条件、合同文件、运保费及出口合规待真实交易双方确认。

## 利润与商业模式

供应商关注单吨毛利和订单净收益；平台可以在商用阶段选择企业订阅、交易服务费以及增值服务。当前的 2% 平台费仅为可理解的测算示例，不是承诺费率。

利润台提供报价前的场景测算，以及订单层面的收益预估。不能将预估毛利标记成实际到账或可提现余额。未来的结算中心应以账务分录和真实支付回调为依据，提供待结算、可结算、提现、退款、汇兑及发票对账。

## 商用迭代优先级

1. **账户与企业边界**：登录、企业成员、角色权限、审计日志、真实供应商核验、成本字段隔离、部署及备份策略。
2. **完整交易闭环**：多品订单、买卖双方协商价、报价转订单、合同模板与签署、取消退款、库存预留时效、文件上传与对象存储。
3. **真实收付与对账**：选择适用于目标市场的支付或银行结算服务，验证回调、幂等账务、平台费用和提现审批。
4. **出口履约**：货代与物流接口、装箱清单、材质证明、原产地证、单证版本记录、第三方检验与争议工单。
5. **国际市场运营**：中英双语、目的国规范、多币种展示与结算汇率来源、搜索引擎页面、询价转化与履约指标。

## 验收与业务指标

本版验收：新企业能申请并完成演示审核；上架商品能被买家搜索；询价能收到演示报价；采购产生可持久化订单并扣减库存；订单可推进并导出草稿；收益能按口径重算；手机页面无整页横向溢出。

商用指标：入驻审核完成率、有效在售 SKU、询价响应时长、询价至合同转化率、成交吨位、订单毛利、准时交付率、回款周期和复购率。当前总览的六个月趋势单独标为示例，不能当作真实业务增长数据。
